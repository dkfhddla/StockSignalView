# StockSignalView MVP 기반 사양

## 목적 및 문제

StockSignalView는 거래 기록, 투자 메모, 수익률 계산을 하나의 플로우로 통합하고, 그 결과를 AI가 생성 가능한 Dashboard Schema로 표현해 개인 투자자가 자신만의 매매 의사결정 근거를 재검토할 수 있도록 한다.  
현재 Phase 1은 시장 대비 상대수익률까지 포함한 포트폴리오 상태를 로컬에서 검증 가능한 방식으로 제공하고, 같은 데이터를 동적 대시보드 엔진의 입력으로 사용할 수 있게 만드는 것이 목적이다.

## 범위

사용자 거래와 종목 데이터를 기반으로 다음 기능을 제공한다.

- 종목 등록 및 분류
- 거래 입력, 수정, 삭제
- 포트폴리오 산출(보유 수량, 평단가, 평가손익)
- 시장 대비 상대수익률 계산
- Dashboard Schema v1 생성 및 검증
- 기본 위젯 기반 보유 종목 대시보드 노출
- 동적 뷰 렌더러
- 기본 알림 조건 설정

## 비목표

- 뉴스 API 연동
- OpenDART 공시 연동
- AI 전략 추천 또는 자동 실행
- 임의 코드 생성 기반 동적 뷰
- 실시간 시세 스트리밍
- 증권사 API 연동
- dry-run 주문
- 증권사 실제 주문
- 사용자 계정/다중 사용자 권한

## 요구사항

### R-001 종목 관리

시스템은 종목 코드, 종목명, 시장 구분을 받아 등록·조회·수정할 수 있어야 한다.  
종목은 관심 종목 플래그와 종목별 메모를 가질 수 있어야 한다.

### R-002 거래 기록

시스템은 매수/매도 거래를 다음 필드를 포함해 기록해야 한다.

- 거래 유형
- 수량
- 체결 가격
- 수수료
- 세금
- 거래 일시
- 거래 메모
- 매수/매도 사유

시스템은 거래 수정 및 삭제를 지원해야 한다.

### R-003 포트폴리오 산출

시스템은 종목별 보유 수량, 평균 매수가, 평가금액, 평가손익, 실현손익, 포트폴리오 비중을 계산해야 한다.

MVP의 원가 및 실현손익 계산 기준은 이동평균법으로 고정한다.

- 매수 거래가 추가되면 기존 보유 원가와 신규 매수 원가를 합산한 뒤 보유 수량으로 나누어 평균 매수가를 재계산한다.
- 매도 거래의 실현손익은 매도 체결가와 매도 시점 평균 매수가의 차이를 기준으로 계산한다.
- 매도 후 남은 보유 수량의 평균 매수가는 유지한다.
- 거래 기록은 계산 결과만 저장하지 않고 개별 거래 단위로 보존해야 한다.
- FIFO, LIFO, 개별 지정법은 MVP 계산 기준이 아니지만, 향후 별도 계산 모듈로 추가할 수 있도록 거래 원장 구조를 훼손하지 않아야 한다.

### R-004 상대수익률 산출

시스템은 종목 수익률과 시장 수익률을 동일 기준 구간으로 계산하고, 상대수익률을 산출해야 한다.

```text
종목 수익률 = (현재가 - 기준일 종목 기준가) / 기준일 종목 기준가 * 100
시장 수익률 = (현재 지수 - 기준일 지수) / 기준일 지수 * 100
상대수익률 = 종목 수익률 - 시장 수익률
```

기본값으로 평가 시작일은 해당 종목의 현재 보유 기간 첫 매수일을 사용한다.  
기준일 종목 기준가는 현재 보유 기간의 첫 매수 체결가로 설정한다.  
KOSPI 종목은 KOSPI 지수, KOSDAQ 종목은 KOSDAQ 지수를 비교 기준으로 사용한다.

### R-005 대시보드

시스템은 Dashboard Schema v1을 통해 보유 종목 목록에서 종목별 평가손익, 상대수익률, 강/약세 상태를 노출해야 한다.  
PC는 표 중심 레이아웃, 모바일은 카드형 레이아웃을 우선 적용해야 한다.

### R-006 Dashboard Schema v1

시스템은 기본 대시보드와 AI 플래너 출력 모두를 `docs/dashboard-schema-v1.md`의 JSON 계약으로 표현해야 한다.

- 스키마에는 대시보드 식별자, 제목, 레이아웃, 위젯 목록, 데이터 요구사항, 생성 출처가 포함되어야 한다.
- 위젯 타입은 `docs/widget-registry.md`에 등록된 항목만 사용할 수 있다.
- 스키마 검증 실패 시 렌더러는 화면을 표시하지 않고 안전한 오류 상태를 표시해야 한다.

### R-007 동적 뷰 렌더러

시스템은 검증된 Dashboard Schema를 받아 허용된 위젯만 렌더링해야 한다.

- 렌더러는 AI가 생성한 코드, HTML, 스크립트, 임의 네트워크 요청을 실행하지 않아야 한다.
- 데이터가 부족한 위젯은 `미산출`, `데이터 부족`, `권한 없음` 같은 명확한 상태를 표시해야 한다.
- 기본 MVP는 AI API 연결 없이 프리셋 Dashboard Schema로 동일 렌더링 경로를 검증할 수 있어야 한다.

### R-008 기본 알림

시스템은 목표 수익률, 손절 기준, 상대수익률 임계치 조건을 정의/저장하고 앱 내부 표시 또는 로그로 확인 가능한 형태로 제공해야 한다.

## 동작 시나리오

### S-001 종목 등록 및 거래 기록

사용자가 종목을 등록하고 해당 종목의 매수·매도 거래를 입력한다.  
각 거래는 위 요구사항의 필수 필드를 모두 저장하고, 수정/삭제 후에도 집계값이 일관되게 재계산되어야 한다.

### S-002 상대수익률 확인

사용자가 현재 보유 기간 첫 매수일 이전/이후 가격 데이터 및 지수를 입력한다.  
시스템은 동일 평가 시작일을 기준으로 종목 수익률, 시장 수익률, 상대수익률을 계산해 대시보드에 노출해야 한다.

### S-003 동적 대시보드 렌더링

사용자가 기본 대시보드를 열거나 투자 상태 질문을 입력한다.  
시스템은 Dashboard Schema를 생성하고 검증한 뒤, 위젯 레지스트리에 등록된 컴포넌트만 사용해 화면을 표시해야 한다.

### S-004 알림 조건 동작

사용자가 목표 수익률, 손절 기준, 상대수익률 임계치를 등록한다.  
조건 충족 시 앱 내부 알림 또는 로그 이벤트가 생성되어야 한다.

### 계약 소유 기준

- 거래/거래 유형/메모/사유 필드, 유효성 규칙은 `backend/app/schemas/`에서 정의한다.
- 종목·포트폴리오 계산 계약은 `backend/app/models/`, `backend/app/services/`에서 정합성을 확보한다.
- 원가 계산 방식은 MVP에서 이동평균법을 기본값으로 사용하며, 계산 서비스는 향후 FIFO/LIFO/개별 지정법을 추가할 수 있도록 거래 원장 입력을 기준으로 동작해야 한다.
- API 노출 계약은 `backend/app/api/`와 클라이언트 연동 계약(`backend` ↔ `frontend/src/lib/`)에서 정합성을 확보한다.
- 기본 레이아웃, 응답성, Dashboard Schema 렌더링은 `frontend/src/app/`, `frontend/src/features/`에서 소유한다.

## 수용 기준

- [ ] 종목 등록, 조회, 수정, 삭제를 포함해 관심 종목 표시 및 메모가 동작한다.
- [ ] 거래 입력 시 유효성 규칙이 지켜지며 거래 수정/삭제 후 집계값이 즉시 반영된다.
- [ ] 포트폴리오 수치(보유 수량, 평단가, 평가금액, 평가손익, 실현손익, 비중)가 일관되게 계산된다.
- [ ] 평균 매수가와 실현손익은 이동평균법 기준으로 계산되며, 개별 거래 원장은 후속 계산법 확장을 위해 보존된다.
- [ ] 상대수익률이 규정 수식으로 계산되며 기본 평가 시작일/기준가가 적용된다.
- [ ] KOSPI 종목은 KOSPI, KOSDAQ 종목은 KOSDAQ 지표로 상대 비교한다.
- [ ] Dashboard Schema v1이 기본 대시보드 구성을 표현하며, 스키마 검증을 통과해야 렌더링된다.
- [ ] 위젯 레지스트리에 등록된 위젯만 화면에 표시된다.
- [ ] 보드/카드/표 형태 화면으로 종목 상태가 확인되며 강/약세 구분이 표시된다.
- [ ] 목표 수익률/손절/상대수익률 기준 조건이 앱 표시 또는 로그로 확인된다.
- [ ] 비목표 항목은 명시된 범위를 벗어나 구현되지 않아야 한다.
- [ ] 거래/종목/수익률 입력 시 소수점 반올림 정책, 음수 수익률 표시, 결측값 처리 정책이 명확하다.

### 유효성 규칙

- 수량·가격은 0보다 커야 하며, 수수료·세금은 0 이상이어야 한다. 수량은 소수점 허용 범위를 구현별로 고정한다.
- 매도 거래 수량은 보유 수량 초과를 허용하지 않는다.
- 시장 구분은 `KOSPI`, `KOSDAQ` 등 유효 값만 허용한다.
- 수익률 계산에 필요한 기준값(기준일, 기준가, 기준 지수)이 없으면 계산 경고를 남기고 대시보드에는 `미산출` 상태를 표시한다.

## 검증 기대치

- `backend/tests`: 수익률 계산(종목/시장 수익률, 상대수익률), 포트폴리오 집계(보유수량/평단가/손익) 단위 테스트를 추가해 수락 기준 항목별로 1:1 매핑한다.
- `backend/tests`: 이동평균법 기준의 추가 매수, 부분 매도, 전량 매도 시 평균 매수가와 실현손익 계산을 회귀 테스트한다.
- `backend/tests`: 잘못된 거래(매도 수량 초과, 음수 값, 누락 입력) 예외 처리 테스트로 데이터 무결성 경계를 검증한다.
- `backend/tests`: 현재 보유 기간 첫 매수일 기본값 설정 및 KOSPI/KOSDAQ 비교 지표 선택 규칙을 회귀 테스트한다.
- `frontend`: PC/모바일 기본 레이아웃 표/카드 노출과 강/약세 상태 표시를 통합 테스트 또는 스냅샷 기반 검증으로 확인한다.
- `frontend`: 유효한 Dashboard Schema는 렌더링되고, 미등록 위젯/잘못된 데이터 요구사항/임의 코드 필드는 거부되는지 검증한다.
- `backend`/`frontend`: 외부 API 없이 수동 입력 또는 모의 데이터 주입으로 핵심 경로를 재현 가능한 실행으로 확인한다.
- `docs/specs/mvp-foundation.md`: 수락 기준을 기준으로 스펙 충족 여부 자체는 문서 일관성 리뷰로 점검한다.

## 에이전트 컨텍스트

- 계산은 외부 실시간 데이터 의존 없이 오프라인/수동 입력 우선 정책을 유지한다.
- AI 플래너는 MVP에서 실제 API 연결 전이라도 프리셋/모의 출력으로 Dashboard Schema 경로를 검증할 수 있어야 한다.
- 후속 기능(뉴스, 공시, 실시간 주문, 계정 다중화)은 본 문서 범위에 추가되지 않는다.
