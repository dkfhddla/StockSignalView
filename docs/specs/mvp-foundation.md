# StockSignalView MVP 기반 사양

## 목표

Phase 1 MVP는 사용자가 종목과 거래를 기록하고, 포트폴리오 상태와 시장 대비 상대수익률을 확인하며, 기본 알림 조건을 관리할 수 있게 하는 것을 목표로 한다.

## 포함 범위

### 종목 관리

- 사용자는 종목 코드, 종목명, 시장 구분을 등록할 수 있어야 한다.
- 사용자는 종목을 관심 종목으로 표시할 수 있어야 한다.
- 사용자는 종목별 메모를 기록할 수 있어야 한다.

### 거래 기록

- 사용자는 매수와 매도 거래를 기록할 수 있어야 한다.
- 거래 기록은 거래 유형, 수량, 가격, 수수료, 세금, 거래 일시를 포함해야 한다.
- 사용자는 거래별 메모와 매수/매도 사유를 기록할 수 있어야 한다.
- 사용자는 잘못 입력한 거래를 수정하거나 삭제할 수 있어야 한다.

### 포트폴리오 계산

- 시스템은 종목별 보유 수량을 계산해야 한다.
- 시스템은 종목별 평균 매수가를 계산해야 한다.
- 시스템은 평가금액, 평가손익, 실현손익을 계산해야 한다.
- 시스템은 포트폴리오 내 종목 비중을 계산해야 한다.

### 상대수익률 계산

시스템은 다음 공식을 기준으로 상대수익률을 계산해야 한다.

```text
종목 수익률 = (현재가 - 평균매수가) / 평균매수가 * 100
시장 수익률 = (현재 지수 - 기준일 지수) / 기준일 지수 * 100
상대수익률 = 종목 수익률 - 시장 수익률
```

- 기준일은 해당 종목의 첫 매수일을 기본값으로 삼는다.
- 후속 버전에서는 사용자가 평가 시작일을 별도로 지정할 수 있다.
- KOSPI 종목은 KOSPI 지수와 비교한다.
- KOSDAQ 종목은 KOSDAQ 지수와 비교한다.
- 초기 MVP에서는 현재가와 시장 지수를 수동 입력 또는 모의 데이터로 대체할 수 있다.

### 대시보드

- 사용자는 보유 종목 목록을 볼 수 있어야 한다.
- 사용자는 종목별 평가손익과 상대수익률을 볼 수 있어야 한다.
- 사용자는 강세/약세 종목을 구분할 수 있어야 한다.
- PC 화면은 표 중심 구성을 우선한다.
- 모바일 화면은 카드형 구성을 우선한다.

### 기본 알림

- 사용자는 목표 수익률 알림 조건을 정의할 수 있어야 한다.
- 사용자는 손절 기준 알림 조건을 정의할 수 있어야 한다.
- 사용자는 상대수익률 기준 알림 조건을 정의할 수 있어야 한다.
- 초기 MVP의 알림은 앱 내부 표시 또는 로그 기록으로 대체할 수 있다.

## 제외 범위

- 뉴스 API 연동
- OpenDART 공시 연동
- AI 요약 생성
- 자연어 기반 동적 뷰 생성
- 실시간 시세 스트리밍
- 증권사 실제 주문
- 사용자 계정과 다중 사용자 권한

## 완료 기준

- 거래 입력 흐름이 문서화된 데이터 항목을 모두 수용한다.
- 수익률과 상대수익률 공식이 구현 기준으로 명확하다.
- 외부 API 없이도 수동 입력 또는 모의 데이터로 MVP를 검증할 수 있다.
- 후속 기능이 MVP 필수 범위와 명확히 분리되어 있다.
