# StockSignalView 프론트엔드 사용자 흐름

## 목적

이 문서는 `docs/specs/stock-signal-view-core-flow.md`와
`docs/specs/mvp-foundation.md`를 바탕으로, 사용자가 실제 화면에서 어떤
순서로 진입하고 이동하며 어떤 상태를 보게 되는지 정의한다.

본 문서는 프론트엔드 실행 흐름과 화면 책임을 다루며, Dashboard Schema 계약
자체는 `docs/dashboard-schema-v1.md`, 렌더링 책임은
`docs/dynamic-view-renderer.md`가 소유한다.

## 범위

- 첫 진입 시 기본 대시보드 확인
- 종목 목록과 관심 종목 필터 확인
- 거래 입력 및 메모 연결
- 투자 상태 질문 또는 프리셋 선택
- Dashboard Schema 기반 동적 대시보드 표시
- 기본 알림 상태 확인

## 비범위

- 회원가입, 로그인, 다중 사용자 권한
- 실시간 시세 스트리밍 화면
- 뉴스/공시 전용 탐색 화면
- 브로커 주문 실행 화면
- AI가 생성한 임의 코드 또는 HTML 실행

## 화면 집합

### V-001 기본 대시보드 화면

- 사용자가 가장 먼저 도달하는 기본 진입 화면이다.
- 기본 프리셋 또는 마지막으로 선택한 안전한 Dashboard Schema를 사용한다.
- PC에서는 표 중심 배치를 우선하고, 모바일에서는 카드 중심 배치를 우선한다.
- 종목 상태 요약, 상대수익률, 메모 존재 여부, 알림 상태를 빠르게 확인할 수
  있어야 한다.

### V-002 종목 목록 화면

- 등록된 종목 목록을 확인하고 관심 종목 여부를 조정한다.
- 시장 구분, 보유 여부, 관심 종목 여부를 기준으로 필터링할 수 있어야 한다.
- 종목 상세 진입 전에도 핵심 상태를 짧게 확인할 수 있어야 한다.

### V-003 거래 입력 화면

- 종목 선택 또는 종목 맥락 안에서 매수/매도 거래를 입력한다.
- 거래 수량, 가격, 수수료, 세금, 거래 일시, 메모를 함께 입력할 수 있어야
  한다.
- 저장 직후 사용자는 이전 화면으로 돌아가거나 대시보드 반영 결과를 볼 수
  있어야 한다.

### V-004 거래 회고 화면

- 특정 종목의 거래 이력과 메모를 시간순으로 확인한다.
- 매수/매도 판단 근거와 현재 성과를 함께 비교할 수 있어야 한다.
- 메모 없는 거래는 후속 회고가 필요하다는 상태를 드러내야 한다.

### V-005 동적 대시보드 화면

- 사용자의 질문 또는 프리셋 선택 결과를 Dashboard Schema 기반으로 표시한다.
- 허용된 위젯만 렌더링되며, 렌더링 실패 시 부분 화면이 아니라 안전한 오류
  상태를 표시한다.
- 동일 데이터라도 질문 의도에 따라 위젯 조합과 레이아웃이 달라질 수 있다.

### V-006 알림 상태 화면

- 목표 수익률, 손절, 상대수익률 임계치의 등록 상태와 최근 평가 결과를
  보여준다.
- `TRIGGERED`, `NOT_TRIGGERED`, `UNAVAILABLE` 상태를 구분해 표시해야 한다.
- 이벤트 로그 중심으로 읽히되, 관련 종목으로 다시 이동할 수 있어야 한다.

## 주요 진입점

- 앱 시작 -> `V-001 기본 대시보드 화면`
- 종목 목록 탐색 -> `V-002 종목 목록 화면`
- 종목 문맥에서 거래 추가 -> `V-003 거래 입력 화면`
- 종목 상태 회고 -> `V-004 거래 회고 화면`
- 질문 입력 또는 프리셋 선택 -> `V-005 동적 대시보드 화면`
- 알림 점검 -> `V-006 알림 상태 화면`

## 표준 사용자 흐름

### F-UI-001 첫 진입과 기본 대시보드 확인

1. 사용자가 앱을 연다.
2. 시스템은 기본 프리셋 Dashboard Schema 또는 마지막 안전한 프리셋을
   불러온다.
3. 시스템은 스키마를 검증한 뒤 위젯을 렌더링한다.
4. 사용자는 보유 종목 상태와 상대수익률, 알림 상태를 한 화면에서 본다.

### F-UI-002 종목 탐색 후 거래 기록

1. 사용자가 종목 목록 화면으로 이동한다.
2. 관심 종목 또는 시장 필터를 조정한다.
3. 특정 종목을 선택해 거래 입력 화면으로 이동한다.
4. 거래와 메모를 저장한다.
5. 시스템은 저장 결과를 반영한 뒤 대시보드 또는 회고 화면으로 복귀시킨다.

### F-UI-003 거래 후 회고

1. 사용자가 거래 저장 직후 종목 회고 화면 또는 대시보드로 이동한다.
2. 시스템은 최신 계산 결과를 표시한다.
3. 사용자는 메모와 현재 성과를 함께 비교한다.
4. 메모가 없거나 계산이 불완전하면 보완이 필요한 상태를 확인한다.

### F-UI-004 질문 기반 동적 대시보드

1. 사용자가 질문을 입력하거나 프리셋을 선택한다.
2. 시스템은 질문 의도를 분류하고 Dashboard Schema 초안을 만든다.
3. 시스템은 스키마를 검증하고 허용된 위젯만 연결한다.
4. 사용자는 질문 의도에 맞는 동적 대시보드 화면을 본다.
5. 질문이 허용 범위를 벗어나면 화면 생성 대신 안전한 거절 또는 보완 질문을
   본다.

### F-UI-005 알림 상태 확인

1. 사용자가 알림 상태 화면으로 이동한다.
2. 시스템은 규칙 목록과 최근 이벤트를 보여준다.
3. 사용자는 충족 상태와 판단 불가 상태를 구분해 확인한다.
4. 사용자는 관련 종목 또는 대시보드 화면으로 다시 이동할 수 있다.

## 상태 전이 규칙

- 거래 저장 성공 후 기본 복귀 위치는 직전 화면 문맥을 따른다.
  - 대시보드에서 진입했으면 대시보드로 복귀
  - 종목 회고에서 진입했으면 회고 화면으로 복귀
- Dashboard Schema 검증 실패 시 `V-005`는 일반 위젯 화면으로 넘어가지 않고
  오류 상태 화면에 머문다.
- 계산 상태가 `PARTIAL` 또는 `UNAVAILABLE`이면 값 자체를 숨기지 말고
  이유가 드러나는 상태 표시를 우선한다.
- 모바일에서는 다중 패널 대신 단일 컬럼 흐름을 유지한다.

## 화면 상태 규칙

### S-UI-001 Loading

- 데이터 조회 또는 Dashboard Schema 검증 중임을 표시한다.
- 이전 데이터가 안전하게 유지되는 경우 스켈레톤 또는 마지막 안정 상태를
  함께 사용할 수 있다.

### S-UI-002 Empty

- 등록 종목 없음, 거래 없음, 알림 없음 같은 초기 상태를 구분해 표시한다.
- 빈 상태는 다음 행동을 유도해야 하지만 제품 소개 페이지처럼 보이면 안 된다.

### S-UI-003 Partial

- 일부 계산값만 있는 경우 `PARTIAL` 또는 `미산출` 상태를 명확히
  표시한다.
- 사용자는 어떤 입력이 부족한지 이해할 수 있어야 한다.

### S-UI-004 Error

- 스키마 검증 실패, 미등록 위젯, 잘못된 거래 입력, 계산 불가 상태를
  구분해 표시한다.
- 기술적 내부 오류를 그대로 노출하지 않고, 사용자가 다음에 할 수 있는 행동을
  함께 제시해야 한다.

## 반응형 규칙

- PC에서는 `position_table`, `relative_return_chart`, `decision_timeline` 조합을
  우선 사용한다.
- 모바일에서는 `position_cards`와 단일 컬럼 위젯 흐름을 우선 사용한다.
- 같은 Dashboard Schema라도 화면 폭에 따라 안전한 레이아웃 조정이 가능해야
  하며, 위젯 의미 자체는 바뀌면 안 된다.

## 금지 동작

- 검증 실패 스키마의 부분 렌더링
- 질문 결과를 코드, HTML, 스크립트로 해석해 실행
- 데이터 부족 상태를 성공 상태처럼 숨겨 표시
- 알림 상태 화면에서 주문 또는 외부 시스템 변경 동작 수행

## 수용 기준

- [ ] 첫 진입 시 기본 대시보드가 검증된 Dashboard Schema를 통해 표시된다.
- [ ] 종목 목록 -> 거래 입력 -> 대시보드 또는 회고 복귀 흐름이 끊기지
  않는다.
- [ ] 질문 기반 동적 대시보드는 허용된 위젯만 사용한다.
- [ ] 스키마 검증 실패 시 부분 위젯 노출 없이 안전한 오류 상태를 표시한다.
- [ ] `PARTIAL`, `UNAVAILABLE`, `EMPTY` 상태가 구분되어 사용자에게 이해
  가능하게 보인다.
- [ ] 모바일과 PC 모두에서 기본 흐름이 깨지지 않는다.

이 문서의 화면 상태, 반응형 의미 보존, 수동 탐색 검사의 상세 분류는
`docs/guidelines/mvp-verification-strategy.md`를 따른다.
