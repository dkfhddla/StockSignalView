# StockSignalView 핵심 사용자 흐름 사양

## 목적

이 스펙은 `docs/product-requirements/stock-signal-view.md`의 핵심 요구사항에서 파생한
사용자 핵심 흐름(등록 -> 거래 기록 -> 메모 연계 -> Dashboard Schema 기반 대시보드 확인)을 정합적으로 승인 가능한
행동 규칙으로 정의한다.

## 범위

다음 사용성/흐름만을 다룬다.

- 종목 등록/조회/수정/삭제
- 거래 입력/수정/삭제와 판단 사유 메모 연결
- 보유/관심 종목 대시보드 노출
- 기본 Dashboard Schema 기반 화면 표시
- 기본 투자 경고 규칙 등록 및 임계치 확인

## 비범위

- 실시간 시세/뉴스/공시 자동 수집
- 브로커 주문 전송 또는 자동매매
- AI 전략 추천, 자동 주문, 임의 코드 생성 기반 동적 뷰

## 사용자 흐름 요구사항

### F-001 종목과 관찰 대상 등록

- 사용자는 종목 코드 또는 종목명을 이용해 종목을 등록할 수 있어야 한다.
- 종목에는 시장 구분(`KOSPI`/`KOSDAQ`)을 지정할 수 있어야 한다.
- 관찰 대상 여부를 토글해 대시보드 기본 노출 대상에 포함/제외할 수 있어야 한다.
- 등록된 종목 정보가 저장되며, 동일 종목 중복 등록 시 사용자 확인 메시지가 표시되어야 한다.

### F-002 거래와 판단 사유 기록

- 사용자는 매수/매도 거래를 입력할 때 최소한 다음 값을 제공할 수 있어야 한다.
  - 거래유형
  - 수량
  - 체결가
  - 수수료
  - 세금
  - 거래일시
- 사용자는 거래에 대한 판단 사유/메모를 함께 등록할 수 있어야 한다.
- 거래 저장/수정/삭제 후 동일 종목의 수익 계산값이 즉시 재산출되어야 한다.
- MVP의 평균 매수가와 실현손익은 이동평균법으로 계산하되, 거래 원장은 개별 거래 단위로 보존되어야 한다.
- 매도 거래의 수량은 현재 보유 수량을 초과할 수 없다.

### F-003 대시보드 복기 흐름

- 사용자는 대시보드에서 종목별로 아래 항목을 한 화면에서 확인해야 한다.
  - 보유 수량
  - 평단가
  - 평가손익
  - 실현손익
  - 종목 수익률
  - 상대수익률
  - 강/약세 상태
- 항목은 거래 최신 상태를 반영한 계산값을 표시해야 한다.
- 대시보드는 Dashboard Schema v1로 표현된 종목별 카드 목록/표 형태로 표시되며, 핵심 상태(손익, 상대수익, 강/약세)가 즉시 확인 가능해야 한다.
- 스키마에 포함된 위젯은 `docs/widget-registry.md`에 등록된 타입이어야 한다.

### F-004 흐름 기반 알림 등록

- 사용자는 기본 알림 규칙을 다음 3개로 등록할 수 있어야 한다.
  - 목표 수익률 도달
  - 손절 기준 도달
  - 상대수익률 임계치 충족/하회
- 임계치가 충족되면 앱 내 표시형 알림 또는 이벤트 로그로 확인 가능해야 한다.

## 동작 시나리오

### S-001 새 종목 등록에서 첫 매수까지

1. 사용자가 종목을 등록한다.
2. 동일 종목 거래를 첫 매수로 등록한다.
3. 거래 메모(매수 사유)를 입력한다.
4. 시스템은 해당 거래를 저장하고, 종목을 대시보드에 표시한다.

### S-002 동일 종목의 매도 및 회고

1. 사용자가 이전 거래가 있는 종목에 매도 거래를 입력한다.
2. 매도 메모(매도 사유, 철수 판단 근거)를 입력한다.
3. 매도 수량이 보유 수량을 넘으면 입력이 거부된다.
4. 정상 입력 시 실현손익, 보유 수량, 평균가가 즉시 갱신된다.

### S-003 상대성과 판단 점검

1. 사용자가 대시보드에서 한 종목의 수익률과 상대수익률을 조회한다.
2. 시스템은 종목 수익률/시장 수익률/상대수익률을 함께 표시한다.
3. 사용자는 현재 상태를 판단 근거와 함께 기록했는지 여부(메모 존재)를 확인한다.

### S-004 Dashboard Schema 렌더링

1. 사용자가 기본 대시보드를 연다.
2. 시스템은 기본 프리셋 Dashboard Schema를 생성하거나 조회한다.
3. 시스템은 스키마와 위젯 타입을 검증한다.
4. 검증된 스키마만 동적 렌더러가 화면으로 표시한다.

### S-005 규칙 조건 충족 확인

1. 사용자가 목표 수익률/손절/상대수익률 임계치를 등록한다.
2. 조건이 충족되면 알림 이벤트가 생성되어야 한다.
3. 사용자는 이벤트 목록에서 충족/미충족 상태를 확인한다.

## 계약 기준

- `docs/product-requirements/stock-signal-view.md`의 핵심 요구사항 REQ-SSV-001~REQ-SSV-005
- `docs/specs/mvp-foundation.md`: 집계 계산, Dashboard Schema, 알림 항목의 상위 규칙
- `docs/dashboard-schema-v1.md`: 기본 대시보드 JSON 계약
- `docs/widget-registry.md`: 허용 위젯 계약
- `backend/app/models/*`, `backend/app/schemas/*`: 거래/종목/산출값 계약의 실구현 소유
- `frontend/src/features/*`, `frontend/src/app/*`: 화면 흐름 및 사용자 액션 계약의 소유
- `backend/app/services/*`: 계산 재계산 트리거/실행 계약의 소유

## 수용 기준

- [ ] 종목 등록/조회/수정/삭제가 실패 없이 동작하고, 관찰 대상 플래그가 대시보드 필터에 반영된다.
- [ ] 거래 입력이 거래·메모를 묶어 저장되며, 거래 수정/삭제 시 대시보드 산출값이 즉시 반영된다.
- [ ] 매도 수량이 보유 수량을 초과할 때 일관된 거부 피드백이 표시된다.
- [ ] 대시보드에서 종목별 핵심 지표(보유 수량/평단가/손익/상대수익률/강약세)가 한 화면에서 확인된다.
- [ ] 기본 대시보드는 Dashboard Schema v1 검증을 통과한 뒤 렌더링된다.
- [ ] 기본 알림 규칙 3종이 등록·저장·충족 상태 확인이 가능하다.
- [ ] 비범위 항목(실시간 연동, AI 전략 추천/자동 주문/임의 코드 렌더링)은 본 스펙 경로에서 사용자 화면에 노출되지 않는다.
- [ ] 모바일/PC에서 모두 대시보드 기본 흐름이 깨지지 않고 접근 가능해야 한다.

## 유효성 및 예외

- 거래 유형은 `매수/매도` 외의 값이 들어오면 저장이 거부되고 오류 메시지가 표시되어야 한다.
- 수량·가격·수수료·세금은 음수일 수 없다.
- 보유 계산을 위해 필요한 값이 결손인 경우 산출은 `미산출` 상태로 표시되고, 다음 동작 가능한 안내를 제공해야 한다.
