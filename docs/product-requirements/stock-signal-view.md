# StockSignalView 제품 요구사항

## 1) 목적

StockSignalView는 개인 투자자가 매수/매도 의사결정 과정과 그 결과를 하나의 제품 흐름으로 관리할 수 있게 만들고, 축적된 거래/메모/상대성과 데이터를 AI가 동적 투자 대시보드로 재구성할 수 있게 한다.

본 문서는 구현 상세를 규정하지 않고, 다음 단계의 스펙/이슈가 다뤄야 할 제품 의도를 정리한다.

## 2) 사용자

- 국내 주식 투자자(개별 투자 성향의 초보~중급자)  
- 거래 기록만 남기거나 메모를 분산 저장해 회고가 어려운 사용자  
- 보유 종목의 시장 대비 성과와 자기 판단의 정합성을 한 번에 확인하고 싶은 사용자  
- 고정된 대시보드가 아니라 질문 의도에 맞는 투자 화면을 만들고 싶은 사용자  

## 3) 성공 목표 및 원하는 결과

- 동일한 화면에서 거래 기록, 투자 메모, 상대 성과 지표를 함께 회고한다.
- 사용자가 매매 판단의 이유와 성과를 시간축으로 연계해 복기할 수 있다.
- 사용자가 시장 대비 상대성과를 통해 보유 판단 품질을 빠르게 판단할 수 있다.
- 사용자가 자연어로 투자 상태를 질문하면 시스템이 안전한 Dashboard Schema를 생성하고, 검증된 렌더러가 동적 화면을 표시한다.
- 최소 동작 경로에서 안정적으로 데이터가 유지되고, 확장 기능(뉴스/공시/AI/브로커 연동)을 기존 흐름에서 분리해 운영한다.

## 4) 제품 범위(필수 요구사항)

### 4.1 핵심 요구사항

- **REQ-SSV-001 (거래·메모 동시 기록)**: 사용자는 종목별로 거래(매수/매도)와 판단 사유 메모를 동일 플로우에서 기록할 수 있어야 한다.
- **REQ-SSV-002 (기초 계산 자동화)**: 시스템은 거래 데이터로부터 평균단가, 보유 수량, 평가손익, 실현손익의 산출값을 제시해야 한다. MVP의 기본 원가 계산은 이동평균법을 사용하되, 모든 거래 원장은 개별 거래 단위로 보존해 향후 FIFO/LIFO/개별 지정법 확장을 막지 않아야 한다.
- **REQ-SSV-003 (시장 대비 지표 제공)**: 시스템은 종목 수익률을 시장 지수 대비 상대 성과로 비교해 표시해야 한다.
- **REQ-SSV-004 (종합 대시보드)**: 사용자는 보유/관심 종목별 상태를 한 화면에서 빠르게 파악할 수 있어야 한다.
- **REQ-SSV-005 (동적 대시보드 스키마)**: 시스템은 자연어 요청 또는 기본 프리셋을 Dashboard Schema v1로 표현하고, 코드 실행 없이 검증된 위젯만 렌더링해야 한다.
- **REQ-SSV-006 (AI 대시보드 플래너)**: AI는 사용자 질문과 투자 데이터를 바탕으로 화면 의도, 위젯 구성, 데이터 요구사항을 제안하되 허용된 스키마와 위젯 레지스트리 밖의 출력을 생성하지 않아야 한다.
- **REQ-SSV-007 (규칙 기반 알림)**: 사용자는 목표 수익률, 손절 기준, 상대수익률 조건의 최소 3개 규칙을 설정하고 임계값 충족을 추적할 수 있어야 한다.
- **REQ-SSV-008 (사용자 데이터 관리 우선순위)**: 초기 버전은 로컬 보안 경계 내에서 안정 동작하고, 확장 기능은 옵션형으로 점진 적용한다.
- **REQ-SSV-009 (AI 보조의 경계 설정)**: AI는 판단을 보조하는 역할로만 제공되며, 투자 결정의 최종 책임은 사용자에게 있음을 일관되게 안내해야 한다.

### 4.2 비목표/범위 제외

- 실시간 뉴스 수집/분석 파이프라인
- 공시 자동 분류 및 알림 엔진(전체 자동화)
- AI 전략 추천의 자동 실행
- 증권사 주문 연동 및 자동매매(현재는 확장 단계로 분리)
- AI가 임의의 화면 코드, 쿼리, 외부 API 호출을 직접 생성해 실행하는 방식

## 5) 가정, 위험, 의존성

- **가정**: 사용자는 기본적으로 장기 보유 또는 단기 트레이드 모두에서 동일한 거래/메모 기록 체계를 활용한다.
- **가정**: 시장 지수 데이터는 최소한 일간 단위로 신뢰성 있게 조회 가능해야 한다.
- **위험**: 실시간 가격 지연 또는 데이터 누락 시 상대성과 해석 정확도가 저하될 수 있다.
- **위험**: 사용자 데이터 누적량 증가 시 계산 성능 및 UI 반응 속도 저하 가능.
- **위험**: AI가 사용자의 의도보다 과도한 투자 판단 또는 허용되지 않은 위젯 구성을 제안할 수 있음.
- **의존성**: 시장 지수/가격 데이터 소스, 로컬 저장 계층 또는 동기화 계층, 향후 확장 모듈(알림/AI/브로커)의 API 계약.

## 6) 미해결 질문

- 시장 대비 벤치마크는 KOSPI 단일 지수로 고정할지, 업종·섹터 지수 옵션을 허용할지?
- 보안·백업 전략은 로컬 단일 저장소로 둘지, 동기화 옵션을 병행할지?

## 7) 다음 단계 소유 조건(Ready for spec)

- 제품 목표, 범위, 비범위가 변경 승인되었는지 여부가 명확해야 한다.
- 핵심 데이터 스키마(거래/메모/지표 저장 구조)의 단일 소유 계약이 확인되어야 한다.
- 벤치마크 결정(기준 지수 및 상대성 계산 규칙)이 확정되어야 한다.
- 알림 임계값 및 사용자별 기본값 운영 정책이 확정되어야 한다.
- Dashboard Schema v1, 위젯 레지스트리, 동적 렌더러의 최소 계약이 확정되어야 한다.
- 위 조건 충족 후 다음 산출물(`docs/specs/*`)로 상세 행동 기준을 분해한다.

## 8) 제품 검증 기준

- 핵심 사용자 흐름(거래 기록 → 투자 메모 연결 → 상대 성과 확인)이 한 화면에서 연속적으로 수행되는지 검증 가능한 설계로 정리되어야 한다.
- 핵심 AI 흐름(사용자 질문 → Dashboard Schema 생성 → 검증 → 렌더링)이 코드 실행 없이 검증 가능한 설계로 정리되어야 한다.
- 시장 대비 상대성과 계산 항목이 동일 입력에서 일관되게 재계산되는지 수치/정합성 관점으로 검증 가능해야 한다.
- 확장 기능(뉴스/공시/AI/브로커)이 핵심 MVP 경로를 방해하지 않는 분리 아키텍처로 정의되어야 한다.
- 데이터 정합성, 지표 계산 실패 대응, 알림 규칙 오탐/누락 대응 범위가 다음 스펙에서 검증 설계로 이어질 수 있어야 한다.
