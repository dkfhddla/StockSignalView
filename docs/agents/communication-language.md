# 언어 사용 정책

이 문서는 StockSignalView 저장소의 대화, 설명, 문서 작성과 코드 리뷰에 적용할
언어 기준을 정의한다. 전역 설정이나 다른 저장소의 언어 정책은 변경하지 않는다.

## 기본 원칙

- 대화와 설명 본문은 한국어로 작성한다.
- 기계 인식, 의미 보존, 검색성, 상호운용성에 이점이 있으면 필요한 영어를
  사용한다.
- 이러한 이점이 없으면 번역투가 아닌 자연스러운 한국어를 우선한다.
- 영어 사용 여부는 단어의 출처가 아니라 기능과 의미 보존 필요성을 기준으로
  판단한다.

## 영어 허용 범위

다음 항목은 영어 원문을 유지할 수 있다.

- 코드 식별자, 파일 경로, CLI 명령어, API·SDK 이름
- 제품명, 프로토콜명, 업계에서 통용되는 기술 용어
- 도구나 스킬이 인식하는 고정 제목과 필드명
- Conventional Commit 타입, 브랜치명, 상태 라벨
- 번역하면 의미, 검색성, 상호운용성이 떨어지는 표현

주변 설명은 한국어로 작성하고, 허용 항목만 필요한 범위에서 영어로 유지한다.

## 고정 기술 제목과 필드

설정 스킬이 사용하는 다음 제목은 허용된 기술 제목이다.

- `Agent skills`
- `Issue tracker`
- `Triage labels`
- `Domain docs`
- `Git workflow`

MR 템플릿의 `Summary`, `Problem`, `Solution`, `Changes Made`,
`Additional Notes`와 도구가 읽는 고정 필드 또는 제어 문자열도 원문을 유지한다.
예를 들어 `Pull requests as a triage surface`,
`PRs as a request surface: no.`, `Related:`, `Closes`, 상태 라벨, CLI 옵션과
JSON 필드명은 자연어 제목이나 설명으로 보지 않는다.

## 문서 작성 기준

- 일반 제목과 설명 문장은 자연스러운 한국어로 작성한다.
- 공식 이름이나 통용 기술 용어는 억지로 번역하지 않는다.
- 한국어와 영어를 함께 써야 할 때는 같은 개념에 같은 표현을 사용한다.
- 고정 식별자와 필드명을 번역하거나 표기만 다르게 바꾸지 않는다.

## 코드 리뷰 분류

- 허용 범위에 속하는 영어는 수정 대상이 아닌 `허용 예외`로 분류한다.
- `Agent skills`, `Issue tracker`, `Triage labels`, `Domain docs`,
  `Git workflow`는 코드 리뷰의 `영어 일반 제목 사용` `hard violation`에서
  제외한다.
- 위 제목이 영어라는 이유만으로 변경을 요청하지 않는다.
- 다른 일반 영어 제목이나 설명 본문은 허용 사유가 있는지 먼저 확인하고,
  기계 인식이나 의미 보존상 이점이 없을 때만 한국어 수정을 요청한다.
- 번역으로 의미, 검색성, 상호운용성이 떨어지면 영어 원문을 유지한다.
