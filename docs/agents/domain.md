# 도메인 문서

공학 스킬이 코드베이스를 탐색할 때 이 저장소의 도메인 문서를 소비하는 규칙이다.

**레이아웃: 단일 컨텍스트**

## 탐색 전에 읽을 문서

- 루트의 `CONTEXT.md`가 존재하면 읽는다.
- 작업 영역과 관련된 `docs/adr/`의 ADR을 읽는다.

파일이 존재하지 않으면 이를 문제로 보고하거나 선제적으로 만들지 않고 계속
진행한다. 용어나 결정이 실제로 정리될 때 `domain-modeling`,
`grill-with-docs`, `improve-codebase-architecture` 스킬이 지연 생성한다.

## 파일 구조

```text
/
├── CONTEXT.md
├── docs/adr/
├── frontend/
└── backend/
```

`CONTEXT.md`는 프로젝트 전체의 도메인 언어를 소유하고, `docs/adr/`는
프로젝트 전체에 적용되는 설계 결정을 소유한다.

## 용어집의 어휘 사용

이슈 제목, 리팩터링 제안, 가설, 테스트 이름에서 도메인 개념을 사용할 때는
`CONTEXT.md`에 정의된 용어를 따른다. 명시적으로 피하도록 한 동의어로 표현을
바꾸지 않는다.

필요한 개념이 용어집에 없다면 프로젝트가 사용하지 않는 언어를 새로 만들고
있는지 검토한다. 실제 공백이라면 `domain-modeling` 작업 대상으로 기록한다.

## ADR 충돌 표시

작업 결과가 기존 ADR과 충돌하면 조용히 덮어쓰지 말고 해당 ADR과 충돌 이유를
명시한다.
