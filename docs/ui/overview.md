# StockSignalView UI 개요

## 목적

StockSignalView의 UI는 개인 투자자가 종목, 거래, 투자 메모, 시장 대비 성과를 한 화면 흐름에서 읽고 관리하도록 돕는다.

이 문서는 PR 12의 Dashboard Schema 기반 문서 체계를 보조하는 시각/상호작용 기준이다. 화면 계약의 1차 기준은 `docs/dashboard-schema-v1.md`, 위젯 기준은 `docs/widget-registry.md`, 렌더링 책임은 `docs/dynamic-view-renderer.md`, 사용자 흐름은 `docs/specs/frontend-user-flow.md`를 따른다.

UI의 핵심 질문은 다음과 같다.

```text
내 보유 종목과 투자 판단은 KOSPI/KOSDAQ 대비 강한가?
```

따라서 화면은 단순 수익률보다 상대수익률, 판단 사유, 알림 조건을 더 잘 연결해야 한다.

## 사용자 경험 원칙

- 사용자는 보유 종목의 상태를 먼저 파악하고, 필요할 때 상세 근거로 내려간다.
- 수익률, 평가손익, 상대수익률은 서로 다른 의미가 분명히 보이도록 표시한다.
- 거래 기록과 투자 메모는 계산 결과와 분리하지 않고 같은 흐름에서 접근하게 한다.
- PC 화면은 반복 확인과 비교에 유리한 표 중심 구성을 우선한다.
- 모바일 화면은 종목별 상태를 빠르게 훑는 카드 중심 구성을 우선한다.
- 후속 뉴스, 공시, AI, 읽기 전용 provider 기능은 MVP 화면보다 낮은 정보 위계에 둔다.

## MVP 화면 범위

- 대시보드: 보유 종목 상태, 평가손익, 상대수익률, 강세/약세 구분을 보여준다.
- 종목 관리: 종목 코드, 종목명, 시장 구분, 관심 종목 여부, 종목 메모를 관리한다.
- 거래 기록: 매수/매도 거래, 수량, 가격, 비용, 일시, 판단 사유를 입력하고 수정한다.
- 종목 상세: 한 종목의 거래, 메모, 성과, 알림 조건을 한 맥락에서 보여준다.
- 알림 관리: 목표 수익률, 손절 기준, 상대수익률 기준을 관리한다.
- 설정/데이터 입력: MVP에서 필요한 현재가, 시장 지수, 모의 데이터를 관리한다.

## 기본 정보 흐름

```text
대시보드
-> 종목 상세
-> 거래 추가 또는 메모 확인
-> 알림 조건 조정
-> 대시보드로 복귀
```

## 첫 화면 원칙

앱의 첫 화면은 소개용 랜딩 페이지가 아니라 대시보드여야 한다. 사용자가 앱을 열면 현재 포트폴리오 상태, 시장 대비 강약, 주의가 필요한 종목을 즉시 볼 수 있어야 한다.

## 후속 확장 위치

뉴스, 공시, AI 요약, 자연어 기반 동적 뷰, 읽기 전용 provider 연동은 MVP 화면에 섞어 넣지 않는다. 후속 기능은 종목 상세 또는 별도 확장 패널에서 시작하고, provider명, 데이터 출처, 값의 기준 시각, 마지막 갱신 시각, 데이터 상태와 조회 상태를 확인할 수 있을 때만 핵심 대시보드에 노출한다.
