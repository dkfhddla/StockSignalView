# StockSignalView 화면 사양

## 대시보드

대시보드는 MVP의 첫 화면이다. 사용자가 보유 종목의 상태를 비교하고, 시장 대비 강한 종목과 약한 종목을 빠르게 구분하게 한다.

PR 12 기준에서 대시보드는 정적 화면 정의가 아니라 Dashboard Schema v1을 렌더링한 결과다. 이 문서의 화면 사양은 `portfolio-overview` 기본 프리셋과 `position_summary`, `position_table`, `position_cards` 위젯의 UI 표시 기준으로 사용한다.

### 주요 영역

- 상단 요약: `position_summary` 위젯으로 총 평가금액, 총 평가손익, 실현손익, 포트폴리오 평균 상대수익률, 계산 불가 종목 수를 표시한다.
- 상태 필터: 전체, 보유, 관심, 강세, 약세, 알림 발생을 전환한다.
- 보유 종목 표: PC 화면의 핵심 영역이며 `position_table` 위젯으로 렌더링한다.
- 종목 카드 목록: 모바일 화면의 핵심 영역이며 `position_cards` 위젯으로 렌더링한다.
- 알림/주의 목록: 목표 수익률, 손절, 상대수익률 조건에 걸린 항목을 표시한다.

### PC 표 컬럼

- 종목명과 종목 코드
- 시장 구분
- 보유 수량
- 평균 매수가
- 현재가
- 평가금액
- 평가손익
- 종목 수익률
- 시장 수익률
- 상대수익률
- 비중
- 최근 메모
- 알림 상태

Provider 확장 데이터가 연결된 경우 provider명, 데이터 출처, 현재가 또는 지수 값의 기준 시각, 마지막 갱신 시각은 표의 별도 메타데이터 영역 또는 확장 컬럼으로 표시한다. 이 항목은 현재 MVP `position_table` 필수 컬럼 계약에 포함하지 않는다.

### 모바일 카드 정보

- 종목명, 종목 코드, 시장 구분
- 평가손익과 수익률
- 상대수익률
- 보유 수량과 평균 매수가
- 최근 메모 한 줄
- 알림 상태

Provider 확장 데이터가 연결된 모바일 카드는 provider명, 데이터 출처, 현재가 또는 지수 값의 기준 시각, 마지막 갱신 시각을 보조 메타데이터로 표시한다. MVP의 수동/모의 데이터 출처와 갱신 시각은 현재가 또는 계산값 근처의 상태 표시로 다룬다.

### 필터 동작

- 전체: 등록된 보유/관심 종목을 모두 표시한다.
- 보유: 보유 수량이 0보다 큰 종목만 표시한다.
- 관심: 관심 종목으로 표시된 종목만 표시한다.
- 강세: 상대수익률이 0보다 큰 종목만 표시한다.
- 약세: 상대수익률이 0보다 작거나 같은 종목만 표시한다.
- 알림 발생: 알림 조건을 충족했거나 데이터 확인이 필요한 종목만 표시한다.

### 정렬 기본값

대시보드의 기본 정렬은 상대수익률 내림차순이다. 사용자는 평가손익, 비중, 종목명, 알림 상태 기준으로 정렬을 변경할 수 있어야 한다.

### 요약 지표 계산 계약

- 총 평가금액은 보유 종목의 평가금액 합계다.
- 총 평가손익은 보유 종목의 평가손익 합계다.
- 실현손익은 매도 거래에서 확정된 손익 합계다.
- 포트폴리오 평균 상대수익률은 보유 비중을 반영한 가중 평균을 우선한다.
- 계산 기준 데이터가 부족하면 값 대신 계산 불가 사유를 표시한다.

### 행 상태

- 정상: 현재가와 시장 지수 기준값이 모두 있어 계산 가능하다.
- 데이터 부족: 현재가, 기준가, 시장 지수 중 하나 이상이 없다.
- 알림: 목표 수익률, 손절 기준, 상대수익률 조건 중 하나 이상이 충족됐다.
- 모의 데이터: 실제 외부 시세가 아니라 수동 입력 또는 샘플 데이터로 계산됐다.

Provider 확장 데이터가 연결된 행은 관련 owner 데이터 묶음의 `data_status`와 `lookup_status`를 추가로 확인한다. 화면 계산에 필요한 상태가 모두 `AVAILABLE`일 때만 provider 데이터를 정상으로 취급한다. `data_status` 또는 `lookup_status`가 `UNAVAILABLE`이면 데이터 부족으로 처리하고, 그 외에는 다음 상태를 별도로 표시한다.

- 갱신 지연: `data_status` 또는 `lookup_status`가 `STALE`이며 마지막 성공 갱신값은 있으나 최신 데이터로 보기 어렵다.
- 일부 데이터: `lookup_status`가 `PARTIAL`이며 일부 대상 또는 일부 필드만 사용할 수 있다.
- provider 오류: `lookup_status`가 `PROVIDER_ERROR`여서 최신 값을 가져오지 못했다.
- 인증 실패: `lookup_status`가 `UNAUTHORIZED`여서 provider 재인증이 필요하다.
- 권한 없음: `lookup_status`가 `FORBIDDEN`이어서 필요한 조회 권한이나 계좌 접근 권한이 없다.
- provider 미지원: `lookup_status`가 `UNSUPPORTED`여서 provider가 요청한 보유 종목, 현재가, 시장 지수 조회를 지원하지 않는다.

### 대시보드 수용 기준

- 사용자는 첫 화면에서 포트폴리오 총 평가금액, 총 평가손익, 평균 상대수익률을 확인할 수 있다.
- 사용자는 종목별 평가손익과 상대수익률을 같은 행 또는 카드에서 비교할 수 있다.
- 사용자는 강세/약세/알림 발생 종목을 필터로 좁힐 수 있다.
- 계산 불가 값은 빈 숫자처럼 보이지 않고 원인을 표시한다.
- PC 화면에서는 표 중심, 모바일 화면에서는 카드 중심으로 표시된다.

## 종목 관리

종목 관리는 투자 대상의 기본 정보를 등록하고 관심 여부와 메모를 관리하는 화면이다.

### 입력 항목

- 종목 코드
- 종목명
- 시장 구분: KOSPI 또는 KOSDAQ
- 관심 종목 여부
- 종목 메모

### 상태

- 빈 목록
- 등록 완료
- 수정 중
- 삭제 확인
- 중복 종목 코드 오류
- 필수 입력 누락 오류

## 거래 기록

거래 기록 화면은 거래 원장을 관리한다. 모든 계산은 이 거래 원장을 기준으로 추적 가능해야 한다.

### 입력 항목

- 거래 유형: 매수 또는 매도
- 종목
- 수량
- 가격
- 수수료
- 세금
- 거래 일시
- 거래 메모
- 매수/매도 사유

### UX 원칙

- 매수와 매도는 같은 폼 구조를 사용하되 거래 유형에 따라 강조 색만 달라진다.
- 수량, 가격, 비용 입력은 숫자 포맷 오류를 즉시 보여준다.
- 저장 전 예상 반영 결과를 간단히 보여준다.
- 수정과 삭제는 원장 변경임을 명확히 알린다.

## 종목 상세

종목 상세는 한 종목의 판단 근거를 모아 보는 화면이다.

### 주요 영역

- 종목 헤더: 종목명, 코드, 시장, 관심 여부, 현재가 입력 상태
- 성과 요약: 평가손익, 실현손익, 종목 수익률, 시장 수익률, 상대수익률
- 거래 타임라인: 매수/매도 기록과 판단 사유
- 메모: 종목 메모와 거래별 메모
- 알림 조건: 목표 수익률, 손절 기준, 상대수익률 조건

## 알림 관리

알림 관리는 MVP에서 앱 내부 표시 또는 로그 기록으로 대체될 수 있다. UI는 실제 외부 발송을 암시하지 않아야 한다.

### 알림 유형

- 목표 수익률
- 손절 기준
- 상대수익률 기준

### 상태

- 활성
- 비활성
- 조건 충족
- 조건 미충족
- 평가 불가: 현재가 또는 시장 지수 데이터 부족

## 수동 데이터 입력

MVP에서는 현재가와 시장 지수가 수동 입력 또는 모의 데이터로 제공될 수 있다.

### 입력 항목

- 종목 현재가
- KOSPI 지수
- KOSDAQ 지수
- 기준 일시

### UX 원칙

- 데이터가 수동 또는 모의 데이터임을 화면에서 명확히 표시한다.
- 계산 불가 상태는 숫자 대신 원인을 보여준다.
- 마지막 갱신 시각을 주요 계산값 근처에 표시한다.
