# StockSignalView UI 컴포넌트 기준

## 컴포넌트 구성 원칙

공통 컴포넌트는 반복되는 투자 데이터 표현을 안정적으로 다루는 데 집중한다. 시각 장식보다 비교, 입력, 상태 파악의 정확성을 우선한다.

## 앱 셸

- 상단 또는 좌측 내비게이션은 대시보드, 종목, 거래, 알림, 설정으로 구성한다.
- MVP에서는 계정 전환, 조직, 권한 메뉴를 제공하지 않는다.
- 화면 제목은 현재 사용자가 수행할 작업을 직접적으로 나타낸다.

## 데이터 표

PC 대시보드의 기본 컴포넌트다.

### 필수 기능

- 정렬
- 필터
- 행 선택
- 숫자 우측 정렬
- 긴 종목명 말줄임
- 빈 값 표시
- 계산 불가 사유 표시

### 표시 규칙

- 금액은 원 단위 구분 기호를 사용한다.
- 수익률은 `%`를 붙이고 소수점 자릿수를 일관되게 유지한다.
- 평가손익과 상대수익률은 같은 색 규칙을 공유하지 않는다. 두 값의 의미가 다르기 때문이다.

## 종목 카드

모바일 대시보드의 기본 컴포넌트다.

### 포함 정보

- 종목명과 코드
- 시장 구분
- 평가손익
- 상대수익률
- 알림 상태
- 최근 메모

### 동작

- 카드를 누르면 종목 상세로 이동한다.
- 주요 숫자는 한 화면에서 줄바꿈 없이 읽히도록 제한한다.
- 부가 정보는 접거나 상세 화면으로 이동한다.

## 상태 배지

상태 배지는 짧고 일관된 용어를 사용한다.

### 권장 배지

- 보유
- 관심
- 강세
- 약세
- 알림
- 데이터 부족
- 모의 데이터
- 값 최신
- 조회 정상
- 값 갱신 지연
- 조회 지연
- 조회 결과 없음
- 일부 데이터
- 인증 실패
- 권한 없음
- provider 오류
- provider 미지원

다음 provider 상태 라벨과 배지 매핑은 Dashboard Schema와 양쪽 validator에 후속 메타데이터 계약이 도입된 뒤 적용하며, 이 문서가 표시 계약을 소유한다.

- `data_status=AVAILABLE`: 값 최신
- `data_status=STALE`: 값 갱신 지연
- `data_status=UNAVAILABLE`: 데이터 부족
- `lookup_status=AVAILABLE`: 조회 정상
- `lookup_status=PARTIAL`: 일부 데이터
- `lookup_status=STALE`: 조회 지연
- `lookup_status=UNAVAILABLE`: 조회 결과 없음
- `lookup_status=UNAUTHORIZED`: 인증 실패
- `lookup_status=FORBIDDEN`: 권한 없음
- `lookup_status=PROVIDER_ERROR`: provider 오류
- `lookup_status=UNSUPPORTED`: provider 미지원

가격·지수 스냅샷의 역할 라벨은 다음과 같이 표시한다.

- `snapshot_role=CURRENT`: 현재가 또는 현재 지수
- `snapshot_role=DAY_BASELINE`: 당일 기준 가격 또는 지수
- `snapshot_role=HOLDING_PERIOD_BASELINE`: 보유기간 기준 가격 또는 지수

각 가격·지수 상태 배지는 같은 스냅샷의 역할 라벨과 기준 시각 근처에 표시한다. `ProviderHoldingSnapshot.captured_at`은 `보유 현황 기준`으로 표시하고 provider 기반 보유 수량과 평균 매수가 가까이에 둔다. Provider 데이터 상태 배지는 provider명, 데이터 출처, 마지막 갱신 시각과 같은 메타데이터 영역에 둔다. 둘 이상의 비정상 상태가 있으면 동시에 표시한다. 자격 증명 표시는 `docs/specs/read-only-market-data-provider.md`의 비노출 경계를 따른다.

## 수익률 표시

수익률 표시는 숫자, 방향, 기준을 함께 표현한다.

### 구분

- 종목 수익률: 평가 시작일 기준 종목 가격 변화
- 시장 수익률: 같은 기간의 KOSPI/KOSDAQ 변화
- 상대수익률: 종목 수익률에서 시장 수익률을 뺀 값

### 금지

- 상대수익률을 단순 평가손익처럼 표현하지 않는다.
- 시장 기준이 없는 상대수익률을 정상 값처럼 표시하지 않는다.
- 상승/하락 색만으로 의미를 전달하지 않는다.

## 입력 폼

입력 폼은 저장 후 계산에 직접 영향을 주므로 검증 상태를 명확히 보여준다.

### 공통 입력

- 텍스트 입력
- 숫자 입력
- 날짜/시간 입력
- 선택 메뉴
- 토글
- 메모 텍스트 영역

### 오류 표시

- 필수 입력 누락
- 숫자 형식 오류
- 0 이하 수량
- 음수 가격
- 매도 수량 초과
- 계산 기준 데이터 부족

## 확인 대화상자

삭제, 거래 수정, 거래 삭제처럼 원장에 영향을 주는 작업은 확인 대화상자를 사용한다.

대화상자는 어떤 값이 바뀌는지 짧게 설명하고, 취소와 확인 액션을 분명히 구분한다.

## 빈 상태

빈 상태는 사용자가 다음 행동을 바로 시작할 수 있게 한다.

### 예시

- 등록된 종목 없음: 종목 추가 액션을 제공한다.
- 거래 기록 없음: 첫 거래 기록 액션을 제공한다.
- 알림 조건 없음: 알림 조건 추가 액션을 제공한다.
- 계산 데이터 없음: 현재가 또는 시장 지수 입력 액션을 제공한다.
